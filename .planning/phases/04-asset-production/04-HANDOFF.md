## What closes Phase 4

1. Finish the saved runner using its focused tests for selection, evidence and false passes. Reuse earlier source results where the existing source-identity and regression rules allow it.
2. Produce one portable Windows inspection build. Verify clean launch, close and relaunch, correct identification of a missing resource and continued access to a valid sibling. Use the same package for acceptance.
3. Independently review the finished code and package, resolve blocking findings and declare the selected cases. Include active Critical, new, changed and affected source and inherited regressions under the local testing policy.
4. Run the Phase 4 IDs in the [case ownership register](../../../tools/phase4/handoff.json). These are eight edge cases, seven UI states and three procedures covering navigation, packaged relaunch and audio. Group compatible observations in the same session. Inspect moving characters and equipped items, corpses, buildings, portals, the world, effects, UI and text. Record the four existing judgments and named listening verdicts, including the 27 new variants, loop seams and mix. A clean initial selected run is final. Batch fixes before focused checks and a fresh final selected run when repairs are needed.
5. Reconcile the 180 asset entries, source evidence, reviewed export and actual results. In `04-COMPLETION.json` copy the later-phase arrays from the register under `deferred`, keyed by phase number. Count only receipts required at this handoff. Known defects in required content and failed retained checks still block closure.

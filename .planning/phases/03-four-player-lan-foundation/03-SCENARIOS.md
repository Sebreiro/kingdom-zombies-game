# Phase 3 saved scenarios

All 32 Phase 3 cases, all 16 inherited Phase 2 cases and 124 affected active Phase 1 cases are selected before real launch. [Selection](03-SELECTION.json) enumerates every selected and omitted source ID, rationale and planned future declaration. Omitted cases receive no pass/skip/reuse credit. The [independent catalog](../../../tools/phase3/required-cases.json) owns exact case/role/image sets; implementation dispatch does not infer required membership.

## Environment and execution contract

Windows development OS, 1280×720 only; no VM. Complete implementation and independently review/fix the whole phase before any game window. Run `node tools/phase3/check.cjs --list`, the strict build and G0 non-window selection. After the source/tool/revision-bound review record exists, `node tools/phase3/check.cjs --all` executes the saved groups. Use `--failed REPORT` for focused failed/blocked cases; retain the original and then execute the whole selected set on the repaired build. Current reports are immutable `.phase3/runs/<platform>/<nonce>/summary.json`; no evidence is reused or overwritten. Commands and exact review binding are in [LAN checks](../../../docs/workflow/lan-foundation-checks.md).

- **G0**, order 0: ; Independent pure fixtures or fresh owned headless subjects.  Exit/cleanup: Release only owned processes and locks.
- **G1**, order 1: solo; Ordinary Escape/Start between the nine inherited rendered scenarios; Quit last.  Exit/cleanup: Normal menu Quit; bounded owned cleanup.
- **G2**, order 2: browser, discovery-host; Back/Cancel/Escape through ordinary menu; retain host/browser where usable. One actual profile restart is required to demonstrate persisted identity with a distinct PID; additional equal-name hosts only for discovery identity/overflow. Exit/cleanup: Close browser and unused diagnostic hosts through ordinary Quit.
- **G3**, order 3: host, guest1, guest2, guest3; Reuse exact four-peer set for movement, timing and focus; ordinary guest leave/rejoin and host end/rehost. Bounded fifth challengers for Full and duplicate identity; two concurrent contenders only after freeing one slot; one replacement after deliberate guest loss. Exit/cleanup: Retain the final intact four-peer set for G4.
- **G4**, order 4: host, guest1, guest2, guest3; Unexpected host loss is destructive and last; use the intact G3 set where available. Fresh four-peer setup only for an isolated focused host-loss rerun; reason recorded in launch manifest. Exit/cleanup: Unexpectedly terminate only the owned host; guests observe Connection lost and recover via ordinary solo/menu; Quit survivors.

G0 pure proofs use deterministic controlled time/independent state; native headless subjects use real separate processes without renderer/physical-input credit. G1 executes all nine inherited rendered scenarios in one process, with Quit last. G2 reuses host/browser; profile restart and browser overflow/equal-name hosts have explicit reasons. G3 preserves four actual participants and adds only stated challengers/replacement. G4 is destructive and last. One invocation owns isolated ports/profiles/evidence and the shared `.phase2/desktop.lock`; overlap refuses safely and an unknown owner is never deleted. Each native subject has bounded waits, logged exit and owned descendant cleanup.

**As a** solo or LAN player, **I want to** control an ordinary survivor, manage real belongings, fight with actual equipment, and continue after a player's death without losing or duplicating survivors or items. *(Roadmap Phase 6 goal, quoted verbatim.)*

<objective>
Close F1, which failed 21 inherited rendered cases including both Critical smoke cases, and the run-report defects (0 reported launches for Phase 6 groups, missing or NaN per-case durationMs).

**F1 decision (rated reversible).** The repair is runner import preparation, not production loading.
- `FoundationAppearanceAssets` loads `res://assets/common/donor-kit.png` and `res://assets/equipment/items-01-10.png` through `ResourceLoader`. That is the standard Godot path for imported textures.
- The shipped game works this way: `phase06.packaged` passed in run 1 with these atlases, and Phase 6 groups that import their own copy do not fail.
- Loading raw PNGs without an import cache would only work in an unimported source tree. It would diverge from the exported PCK, whose raw PNGs are not exported, and would bypass the import settings.
- The inherited runners are the only launchers that still start the unimported checkout. The layout policy keeps generated import state out of the tracked tree, and engine-defects.md requires every harness import to use the single-threaded policy.
- So both inherited runners reuse the existing `prepareProject` helper in `lan-checks/network.cjs`, which routes through the asset-pipeline command wrapper.

Output: prepared-project launches for the Phase 2 and Phase 3 rendered suites, and complete timing and launch facts in the shared report.
</objective>

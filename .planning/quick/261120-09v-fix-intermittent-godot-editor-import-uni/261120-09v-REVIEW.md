## Warnings

### WR-01: The accept-as-false path trusts a key spelling that differs from Godot's parser, so a later threaded assignment can pass

**File:** `tools/phase4/check.cjs:176-182`

**Issue:** When any matched assignment exists and every match is exactly `false`, the policy returns without appending (line 181). The key matching does not follow `VariantParser::parse_tag_assign_eof` (core/variant/variant_parser.cpp:1891-1960) in three ways:
- **Whitespace.** Godot drops every character `<= 32` from a key, anywhere in it (line 1933, `if (c > 32)`). The JS code only trims the ends.
- **Quoted keys.** Godot unquotes a key written as `"..."` (lines 1934-1946). The JS code keeps the quotes.
- **Section headers.** Godot ends a tag at `]` and accepts a `; comment` after it. The JS regex `^\[([^\]]+)\]$` does not match `[editor] ; x`, so the previous section stays active.

`_load_settings_text` is last-write-wins, so any of these spellings placed after a matched `false` gives the value Godot actually uses. The probe confirmed that both of these are accepted and left byte-identical:
```
[editor]
import/use_multiple_threads=false
"import/use_multiple_threads"=true
```
```
[editor]
import/use_multiple_threads=false
import/ use_multiple_threads=true
```
Godot reads both as `editor/import/use_multiple_threads=true`. The same happens with a root `editor/import/use_multiple_threads=false` followed by `[editor] ; note` and `import/use_multiple_threads=true`.

When no assignment matches, the appended block is last and overrides these spellings. The gap exists only on the "already false" path.

**Fix:** Either change one thing:
- **Option 1:** Normalize keys the way Godot does: unquote a leading `"..."` key, otherwise remove every character `<= 0x20`, and parse a header as `[` up to the first `]` while ignoring the rest of the line.
- **Option 2 (simpler and robust):** Require the last matched assignment to be the last assignment in the file. Otherwise append the block anyway, since appending a redundant `false` is harmless.

For example, normalize keys like this:
```js
const rawKey=line.slice(0,eq).trim();
const key=rawKey.startsWith('"')?JSON.parse(rawKey):rawKey.replace(/[\x00-\x20]/g,'');
const header=/^\[([^\]]*)\]/.exec(line); // allow trailing "; comment"
```
Add self-test cases for the quoted key, the spaced key, and a header followed by a comment.

### WR-02: Feature-tag overrides of the setting are neither rejected nor neutralized

**File:** `tools/phase4/check.cjs:176-183`

**Issue:** `GLOBAL_GET` expands to `get_setting_with_override` (core/config/project_settings.h:265). That function returns the value of any `<name>.<feature>` key whose feature the OS reports, ahead of the base key (core/config/project_settings.cpp:415-431). Override keys are registered from any setting name that contains a dot (project_settings.cpp:324-340). The pinned Windows editor reports the `windows` and `editor` features.

The policy compares only the exact base key. A project containing
```
[editor]
import/use_multiple_threads.windows=true
```
(or `.editor=true`) gets the base `false` block appended. The probe confirmed the append. Godot still imports with multiple threads because the override wins over the base key. If a matching `false` is also present, the file is left unchanged and the override still applies. The probe confirmed this case too.

**Fix:** Treat any computed key equal to `EDITOR_IMPORT_THREADS` or starting with `EDITOR_IMPORT_THREADS+'.'` as a match, and apply the same `false`-only rule. Alternatively, reject every feature-override form outright with `EDITOR_IMPORT_THREADED`:
```js
const full=section?section+'/'+key:key;
if(full===EDITOR_IMPORT_THREADS||full.startsWith(EDITOR_IMPORT_THREADS+'.'))values.push(line.slice(eq+1).trim());
```

## Info

### IN-01: Valid single-thread spellings are rejected

**File:** `tools/phase4/check.cjs:178,181`

**Issue:** A value is compared as the whole rest of the line. These valid settings are rejected with `EDITOR_IMPORT_THREADED` (probe-confirmed):
- `import/use_multiple_threads=false ; note`. Godot skips the trailing comment at variant_parser.cpp:1910-1922.
- `import/use_multiple_threads=0`. `GLOBAL_GET` converts int 0 to `false`.

This fails closed and matches the locked "exactly false" decision, so it is not a correctness risk.

**Fix:** Optionally remove a trailing `;...` comment from the value before comparing it. Keep rejecting non-boolean forms.

### IN-02: A `project.binary` next to `project.godot` makes the policy ineffective

**File:** `tools/phase4/check.cjs:172-175`

**Issue:** `_load_settings_text_or_binary` loads `project.binary` first and reads `project.godot` only when the binary file is missing (core/config/project_settings.cpp:997-1008). If a run-owned project ever contains `project.binary`, for example from a copied export tree, Godot never reads the appended text. No current caller copies one.

**Fix:** Reject with `EDITOR_IMPORT_PROJECT` when the project directory contains `project.binary`:
```js
need(!fs.existsSync(path.join(project,'project.binary')),'EDITOR_IMPORT_PROJECT',name+' project.binary');
```

### IN-03: Other Godot project selectors bypass the `--path` ownership check

**File:** `tools/phase4/check.cjs:168-171`

**Issue:** A positional argument ending in `project.godot` calls `set_cwd(dir)` after `--path` has been processed (main/main.cpp:1800-1812). That moves Godot to a project the policy never inspected. `--main-pack` (main.cpp:1864) is a similar case. The policy only checks `--path`. No current caller passes either argument.

**Fix:** For `--import` commands, reject any argument other than the `--path` value that ends in `project.godot`, and reject `--main-pack` and `--upwards`/`-u`.

### IN-04: A hard-linked `project.godot` would make the append write through to another file

**File:** `tools/phase4/check.cjs:174,184`

**Issue:** `lstat().isFile()` is true for a hard link. `inside()` rejects reparse points but not file aliases. If a case ever hard-links `project.godot` from `src/godot-game`, the append would change the tracked source file. Other Phase 4 code already treats hard links as aliases (`integration.cjs:70,147`). No current caller hard-links this file.

**Fix:** Also require `fs.lstatSync(file).nlink===1`.

### IN-05: The run record does not show that the harness rewrote `project.godot`

**File:** `tools/phase4/check.cjs:184,194-219`

**Issue:** The append happens silently. `<name>.command.json` does not record it, so a run's evidence cannot show whether the policy appended the block or found an existing `false`. The file is also modified before `environment()` and `spawn`, so if either fails, the change has no record at all.

**Fix:** Return `'appended'` or `'present'` from `editorImportPolicy` and add it to `record`, for example `importThreadPolicy`.

### IN-06: The self-test writes under the repository and misses several cases

**File:** `tools/phase4/check.cjs:575-612`

**Issue:** Scratch directories go under the hardcoded `ROOT/.phase4/tdd/editor-import`. Only each run's UUID subdirectory is removed, so an empty `editor-import` directory remains after every run (observed). Cases that are not covered:
- a relative `--path`
- `--path` given twice
- a junction in the project path
- a BOM file
- a `true` value in the `[editor/import]` section form
- the spellings in WR-01 and WR-02

`.phase4/` is git-ignored, so the leftover directory is harmless.

**Fix:** Add the missing cases. Optionally create the scratch directory with `fs.mkdtempSync` under `.phase4/tdd/` so nothing is left behind.

### IN-07: The BOM strip is dead code

**File:** `tools/phase4/check.cjs:175,177`

**Issue:** `new TextDecoder('utf-8',{fatal:true})` uses the default `ignoreBOM:false`, which already consumes a leading BOM. `text.replace(/^﻿/,'')` therefore never matches.

**Fix:** Remove the `replace`, or pass `{ignoreBOM:true}` if the intent is to strip the BOM explicitly.

# Quick Task 261119-15c: Agent cleanup rules

Agents must now delete ignored task outputs and remove their worktrees at task end, after recording results and reproduction steps. A dry-run-first command applies the rules.

## Changes

- New canonical page [workspace cleanup](../../../docs/workflow/cleanup.md): timing, evidence and reproduction before deletion, the keep/delete table, worktree placement and removal, processes and environment, and the command.
- Indexed from the [agent guide](../../../AGENTS.md) and linked from [AI collaboration](../../../docs/workflow/ai-collaboration.md), the [GSD workflow](../../../docs/workflow/gsd.md), [verification](../../../docs/workflow/verification.md) and the [local testing strategy](../../../docs/workflow/local-testing.md). The "preserve reports" sentences now last until the task ends.
- `tools/workspace-cleanup.cjs` with 13 `node:test` cases in `tools/workspace-cleanup.test.cjs`.
- `.gitignore` now ignores every top-level `.phaseN` folder; `dev` previously covered only `.phase1`–`.phase3`.

## Review

An independent review ([findings](261119-15c-REVIEW.md)) reproduced three blockers: a worktree nested in an output folder was deleted, worktree cleanliness depended on `status.showUntrackedFiles`, and removing a worktree containing junctions left its folder behind while reporting success. It also raised warnings for case-sensitive cache names, the active-checker lock and the `.gitignore` gap. Commit `855b177` fixes all of these plus assume-unchanged files, in-progress Git operations, refusal before any deletion and Git failures exiting 1. Each has a regression test. Remaining info items are not changed: the worktree list is parsed without `-z`, so a C-quoted path is falsely refused rather than deleted.

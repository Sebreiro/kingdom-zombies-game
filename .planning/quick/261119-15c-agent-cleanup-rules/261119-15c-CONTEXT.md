# Quick Task 261119-15c: Agent cleanup rules for ignored outputs and worktrees - Context

**Gathered:** 2026-11-19
**Status:** Ready for planning

<domain>
## Task Boundary

AI agents leave ignored phase outputs (run reports, probes, checkpoints, scratch) and git worktrees behind after their work ends. The main checkout held about 74 GB under `.phase4/` alone, plus a leftover worktree in the system temp folder. Add project cleanup instructions that agents must follow, plus a tool that applies them, on a separate branch with a pull request to the default branch `dev`.

</domain>

<decisions>
## Implementation Decisions

### Run outputs and reports
- Delete all ignored task outputs at task end, including reports that committed records cite. Do not keep cited evidence after the task.
- Committed records and the pull request must instead state how to reproduce each check, so the creator can rerun it.

### Worktrees
- Remove an agent-created worktree when its task ends, once its commits are pushed (or merged back) and nothing uncommitted remains. The branch and PR survive the removal.

### Tooling
- Add a cleanup script that is a dry run by default and deletes only with an explicit flag, with automated tests.

### Claude's Discretion
- Durable workspace-local caches (`.phase1/cache`, `tools`, `packages`, `feed`, `http-cache`, `cli-home`, `dotnet-home`) hold pinned prerequisites and the Linux VM disk. They are not task outputs and stay.
- Build outputs (`bin/`, `obj/`, `.godot/`) are regenerable caches; delete them only with an explicit option.
- The script removes only worktrees named explicitly, so it cannot remove a worktree that another session is using. A dry run lists every linked worktree with its state.
- This task changes no existing ignored files in the main checkout; the open Phase 4 branch still uses them.

</decisions>

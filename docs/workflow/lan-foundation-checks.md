# LAN foundation checks

The [Phase 3 scenarios](../../.planning/phases/03-four-player-lan-foundation/03-SCENARIOS.md), [saved selection](../../.planning/phases/03-four-player-lan-foundation/03-SELECTION.json) and [independent catalog](../../src/godot-game/tools/lan-checks/required-cases.json) define exact obligations. Follow the [local testing strategy](local-testing.md): implement and independently review/fix the whole phase before any game window. Routine local runs use Windows at 1280×720 without a VM. Selection includes every new/changed/affected case, all 16 inherited Phase 2 cases and the explicitly enumerated active Phase 1 integrity cases. Omitted source IDs have individual reasons and earn no execution credit.

Connection delivery is explicit at the framework-only port. Baselines, admission acknowledgments, commands, liveness and lifecycle messages use reliable delivery. Recurring complete `state` snapshots use ordered, non-retransmitted delivery so an obsolete snapshot cannot hold newer state behind reliable acknowledgments. Godot's default channel separates these transfer modes; see its [MultiplayerPeer channel contract](https://docs.godotengine.org/en/latest/classes/class_multiplayerpeer.html#class-multiplayerpeer-property-transfer-channel). The guest still validates complete snapshots, readiness, actor ownership, session, monotonic revision and elapsed counters before installation. Missing an intermediate state does not prevent a later complete state from installing, and late older state cannot rewind it. Normal publication is bounded to one per host update at a 16 ms cadence, with accepted intent coalesced into the next post-step publication.

The native adapter frames every control and state payload with an eight-byte magic/version/flag/decoded-length header. Brotli Fastest is used only when smaller; raw fallback preserves the full 2–32768-byte application contract. Native frames are bounded to 32776 bytes. Decoding rejects unknown headers, invalid lengths, truncation, corruption, trailing data and output exceeding the declared bound before dispatch; Brotli must report completion with exact consumed/written counts. The existing `core.protocol` proof exercises this production codec, seeded four-player and Unicode snapshots below 1392 bytes, exact control/state recovery and maximum-size raw fallback. Rare larger valid frames retain native transport support; delivery modes and application validation remain unchanged.

The draw observer consumes a request only after exact nonce/checkpoint validation and successful deletion, before capture. Actual Windows sharing/lock violations (HResult low word 32/33) defer to the next draw within the existing capture deadline. The request remains intact and no capture begins while its read or deletion is locked. Other IO/access errors and malformed requests propagate. `runner.integrity` uses real owned files and locks, release/recovery and duplicate-consumption checks alongside atomic acknowledgment controls.

Join progress clears when the actual coordinator becomes ready, including the first tick after play hides the browser, and on fresh browser entry. Recoverable errors persist while idle until explicit navigation or another attempt. The headless `network.discovery-profile` regression drives a genuine baseline-to-ready transition through the production menu, return action and fresh browse, and checks error retention and navigation clearing. Its native projection checks all four local bindings and P1–P4/You rectangles at both world limits. Marker placement uses the current projected camera, actual label width and logical viewport; it changes horizontal label offsets only. Centered labels, offscreen actors, vertical stacking, actor coordinates, camera smoothing and clamps retain their existing behavior. `core.input` covers edge/center positions, label widths and viewport widths without a window. These structural checks do not replace actual image review.

`--case` accepts exact comma-separated IDs and rejects zero, unknown or duplicate IDs. Groups are core, adapters, network, runner and rendered. Selectors cannot be combined. No-window groups never launch a game window. A rendered/full command fails closed before launch unless `.planning/phases/03-four-player-lan-foundation/03-REVIEW.json` records complete independent whole-phase review, the current source/tool/revision fingerprints, a named reviewer, resolved findings and the hash of its actual Markdown review. The runner also validates and hashes the saved selection before launch. Task 3 authors the actual review record after review/fixes; implementation does not preapprove itself.

The small phase-owned runner is not Phase 5's general catalog/reuse framework. G0 runs build/pure/file/socket/real-headless/runner checks. G1 runs all nine inherited rendered scenarios in one solo process with ordinary resets and Quit last. G2 reuses real host/browser processes; profile restart needs a different PID with the same owned profile root, and extra equally named hosts provide browser overflow. G3 uses host plus three guests, adding only capacity/race/identity challengers and a replacement after deliberate guest loss. G4 unexpectedly terminates the owned host last, reusing the intact G3 set when available. Every extra launch has a recorded reason. A focused G4 execution needs its own four-peer setup.

Inherited Phase 1 commands are independent. Phase 2 core and runner groups also run independently, followed by its one rendered group. The Phase 2 rendered group and Phase 3 native groups require passing inherited Phase 2 core cases and these selected integrity prerequisites: `engine.source-policy`, `engine.generated-origin`, `engine.generated-boundary`, `rules.godot-callsite-boundary`, `graph.visibility-inventory`, `graph.allowed-composition` and `rules.source-format`. Their exact dependency IDs and blockers are saved per invocation. Ordinary failures in other independent commands do not abandon later checks. A missing child report leaves that command's cases blocked with its actual launch/process diagnostics; an assertion failure retains its original failed report. Dependent unexecuted groups have explicit blocked outcomes and no process/pass credit. The outer summary always retains accumulated child report hashes, process records and stdout/stderr logs, returns failure for any inherited failure/blocker, and completion rejects that aggregate even if independent native scenarios pass.

Each invocation creates exclusive immutable `.local/runs/lan-checks/<platform>/<nonce>/` outputs in the checkout that ran it: input snapshot, selected result records, actual process/launch logs, native-input acknowledgements, read-only process/draw streams and PNG/state checkpoints. Case-plus-peer membership uses exact sets. A duplicate guest cannot replace an absent fourth peer; a headless result cannot satisfy rendered or physical-input obligations. Required PNGs must decode as nonempty 1280×720 images with valid chunk CRCs, immutable image/state hashes and matching process/profile/session/actor/binding/revision/draw identity. G4 deliberately binds the terminated host's pre-loss image and each guest's post-loss menu image; no post-loss image is claimed for a dead process.

The persistent Windows helper pins actual PIDs, process start identities and native window handles. `physical-SendInput` means scan-code events delivered through the foreground OS input stream; it is distinct from targeted `window-message` delivery and `synthetic-native-ParseInputEvent`. A helper delivery acknowledgement alone never proves that Godot accepted the event: native callbacks, held polling and authoritative changes are separately observed. Background messages must demonstrate sustained holds before use. An explicit synthetic fallback is allowed only for simultaneous-control/moving-join diagnostics, without physical-input credit. Native focus clearing and canonical authority stay active.

Physical foreground operations share one coordinator queue across all helpers; a focus-plus-click sequence and a text-entry sequence keep that ownership through completion. For the final-slot race, prepare each ordinary Join address control serially using physical click/Tab, then dispatch Enter concurrently to the two owned PIDs with native window messages. Record both actual native handler acknowledgments, focused preparation draw frames and exact driver records. This race has window-message provenance and no physical-input credit; separate required genuine foreground input/focus/timing tests remain mandatory. Unsupported targeted delivery fails this scenario rather than changing ownership checks or claiming synthetic delivery was physical.

The corrected final selection includes 433 affected active Phase 1 cases and keeps 243 explicit active omissions plus eight future Phase 5 declarations. Body-length, all six shared generated-permission analyzer families, analyzer source/input/boundary, generated callsite/origin/companion, register, bounded-exemption and exact shared-source/test-fixture consumers are assessed explicitly. Prelaunch rejects every known affected omission even when an excuse is nonblank. Historical earlier analyzer runs supply no reuse credit.

Stopped-position comparisons reference immutable observer/host samples that must match the actual completed-draw NDJSON frames. Reconciliation binds the current origin profile/session/actor/binding, exact native release record and host-accepted zero-direction intent before deriving positions/revisions. Observations must follow release acknowledgment; uncertainty is nonnegative and at most 1 ms. The inclusive 50-subunit/500-ms bounds remain unchanged. Checkpoint JSON is acknowledged by same-directory atomic rename only after the PNG and complete metadata writes; the external timing end bracket follows the full image/state read and validation.

Every owned game process has an immutable terminal record. Ordinary termination requires the production Quit-handler acknowledgment and zero exit without signal. A deliberate guest/host loss is declared with its exact scenario before the owned kill; emergency cleanup and unexpected prior exits invalidate every affected case, including cases whose final capture was already collected. Terminal process outcomes and native logs are independent evidence requirements.

Timing uses one external `process.hrtime.bigint()` coordinator clock. The conservative interval starts before delivery and ends after completed-draw PNG acknowledgement, including all polling/scheduling/capture delays and a 1 ms clock allowance. No startup-relative peer clocks are subtracted. Exact 250 ms and 50-subunit/500 ms equality passes; the smallest represented overrun fails without rounding. Every required origin/observer start, reversal, stop and real focus-stop needs a visible in-camera actor and bound image/transform evidence. Actual driver feasibility and these rendered limits remain unproved until Task 3 executes them after review.

The shared `.local/locks/desktop.lock` in the repository's shared root (the main checkout's `.local/`) coordinates inherited and new native runs across every checkout of the repository. Its release verifies the recorded owner and file identity; changed/foreign locks remain intact. Profiles, ports and output paths are invocation-owned, bounded waits stop failing subjects, and cleanup targets only owned children/descendants. Never kill Godot globally. Actual nonzero, crash and timeout controls execute real children; counterfeit malformed records prove rejection only and cannot supply successful production execution.

Completion requires one fresh entire-selected-set final report on the repaired source, original/focused history references, current source/tool/OS/revision and the saved selection/review hashes. `.planning/phases/03-four-player-lan-foundation/03-EVIDENCE.json` references that final report, immutable history, selection, actual visual-review artifact and per-image review rows containing exact case, role, checkpoint, image hash, report hash, reviewer, verdict and notes. Inherited results use their original qualified phase/source IDs and real report/process references. Actual readability, Unicode/focus/overflow, actor markers/roster and camera appearance require inspection; decoded pixels or state cannot replace judgment. Any selected failure, missing peer/image, stale identity, unreviewed image or unresolved later failure blocks acceptance.

Preserve failed reports until task end, then record them before [cleanup](cleanup.md). Continue independent scenarios while usable, batch repairs, run failed/blocked/newly affected checks, then rerun the full selected set on the repaired build. An initially clean full selected run already supplies that pass. These local results give no hosted/Linux, physical mixed-computer LAN, complete A-38/A-45 campaign, packaging, reference hardware or endurance certification; those obligations retain their separate owners.

Author final evidence in this order: commit the repaired source and tests; pin the build's `SourceRevisionId` to that exact source commit before building; strictly build and independently review that revision; author the Markdown review and `03-REVIEW.json` naming that reviewed revision and exact source/tool hashes; commit those review artifacts; keep the same build pin for the mandatory strict rebuild and fresh `--all` on that metadata descendant. Prelaunch requires `buildRevision` to equal the immutable reviewed source revision, checks both revisions' committed inputs and the review/report bytes in the execution commit, and permits only the explicit metadata paths in `src/godot-game/tools/lan-checks/revisions.cjs` between them. It copies the original review JSON and Markdown into the invocation directory without rewriting either. The final report binds these immutable copies, so a later canonical review edit does not substitute a different prelaunch review.

The .NET SDK stamps both `AssemblyInformationalVersion` and GitHub SourceLink metadata. Before the initial reviewed-source build, set `$env:SourceRevisionId = (git rev-parse HEAD).Trim()` and `$env:CustomAfterMicrosoftCommonTargets = Join-Path $PWD 'src/godot-game/tools/lan-checks/reviewed-source.targets'` in PowerShell. In a POSIX shell use `export SourceRevisionId="$(git rev-parse HEAD)"` and `export CustomAfterMicrosoftCommonTargets="$PWD/src/godot-game/tools/lan-checks/reviewed-source.targets"`. The phase-only target pins the repository's `SourceRoot.RevisionId` after SDK Git discovery and preserves real GitHub source links; SDK discovery otherwise uses the newer actual HEAD even when the assembly property is pinned. `check.environment` supplies that target to every inherited child build. Keep the original source stamp and target import through strict builds, `--all` and closure; do not reset the stamp after metadata commits. The report's `revision` still records actual execution HEAD, and exact DLL bytes/tool hashes remain mandatory. After closure, rebuild and validate with the final report's original `buildRevision` and target import. Real SDK controls with an actual GitHub remote prove exact equality through review/closure commits, reject SourceLink HEAD drift despite a pinned assembly stamp when the target is omitted, and validate the original evidence after restoring the exact pinned bytes. No source-link disabling or binary hash equivalence is used.

After actual image inspection, author the visual review, evidence index and summary, and commit the permitted closure documents. Validate completion again from that closure checkout. Validation keeps the actual tested revision and original nonce/report hashes, reports both tested and validated revisions, and grants no new execution or general reuse credit. The tested commit must exist and be an ancestor; every intervening path (including reverted changes) must be on the explicit metadata list; current source/tool/selection/scenario/OS inputs must match and the relevant bytes must match both committed trees. Unknown Git state, unrelated/nonexistent revisions, undeclared paths and dirty relevant inputs fail closed. Inherited input fingerprints are checked against the original execution commit, including their broader documentation inputs. Save ignored runtime evidence with its original paths/bytes; tracked metadata references it without copying or manufacturing a passing run.
